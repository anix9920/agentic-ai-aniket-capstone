Overspend

The Solution

An end-to-end optimization agent, zero setup

A multi-agent pipeline that reads monitoring data, detects cost / capacity / performance issues, grounds its advice in a policy knowledge base, and proposes an approved action plan.

The Brain

Every rule is readable code

No magic — each agent is a threshold-based detector you can open and edit. Changing a threshold changes the demo.

SignalThresholdRecommended action
Monthly cost> mean + 1 std devReview spend
Cost increase> 30% vs last monthInvestigate cost anomaly
CPU / memory average< 10% / < 20%Downsize resource
CPU average< 5%Shutdown (idle)
CPU or memory> 85%Scale up
Storage growth> 20%Review lifecycle policy
Latency> 1000 msCaching → scale → optimize → redesign
Availability< 99.9%Review HA configuration

RAG · Retrieval-Augmented Generation

Grounded advice, embeddings that just work

Recommendations are grounded in a policy knowledge base (data/knowledge/*.txt) — the agent retrieves the relevant clause before suggesting an action, then cites its source.

🌐

OpenRouter embeddings

Real vectors from a hosted model when OPENROUTER_API_KEY is set in .env.

🔤

Hashing fallback

256-dim bag-of-words vectors via a deterministic hash. No ML model — works fully offline.

📏

Cosine search

Chunks are embedded once at startup into an in-memory index; queries rank by 1 − cosine similarity.

🔧

Resolved engineering challenge: an earlier version used ChromaDB, whose native Rust/SQLite/ONNX backend crashed the process on some Windows setups. Replaced with an in-memory vector index that stays dependency-free — it uses real OpenRouter embeddings when a key is present and a pure-Python hashing embedder otherwise. The backend now starts reliably on any machine. (chroma_db/ is no longer used.)

Human-in-the-loop

Nothing changes without approval

The Approval Agent queues every recommendation as pending. A human approves or rejects each one; only approved items become the final action plan.

📋

1 · Pending

All recommendations queued for review.

🧑‍💼

2 · Decide

Human clicks Approve or Reject per resource.

🚀

3 · Action plan

Approved items only → final plan.

# main.py — the approval endpoint
@app.post("/approve")
def approve(request):
    decision = workflow.approval_agent.decide(request.resource_id, request.approved)
    return {"decision": decision, "action_plan": workflow.approval_agent.get_action_plan()}
Tech Stack

Small, free, and beginner-friendly

Nine Python dependencies — that's the whole stack. Everything runs on a laptop with Python 3.10+.

Orchestrates the 8-node workflow graph.

⚡

Lightning REST backend & server.

The whole UI — ~190 lines.

✅

Request validation.

Requests

UI ↔ API calls.

🛰️

langchain-openai

OpenAI-compatible client → OpenRouter (LLM + embeddings).

🔑

Loads model & key config from .env.
